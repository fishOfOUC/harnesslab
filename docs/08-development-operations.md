# 08 本地开发与运维

## 1. 当前状态与准备条件

仓库目前只有设计文档。下列目录、命令入口和部署配置需要在实施阶段创建；当前可独立执行的 LM Studio 检查见 [接入文档](04-rag-lm-studio.md)。

准备 Python 3.11 环境、uv、所选前端工具链支持的 Node.js 版本、LM Studio 与 Embedding 模型，以及独立 Chat 模型。Node.js 与前端依赖版本在 M0 根据官方支持范围选择并锁定。

本机原生运行作为首条路径；Docker Desktop 只用于后续服务模式和沙箱，不作为 P0 必需条件。不要预估显存就断言可同时运行两个模型，应先测量。

## 2. 依赖管理

拟用核心包：`langchain`、`langgraph`、`langchain-openai`、`langgraph-checkpoint-sqlite`、`fastapi`、`uvicorn`、`pydantic-settings`、`httpx`、`qdrant-client`、文本/PDF 解析库和中文 BM25 所需依赖。

P1 按功能增加 `langchain-mcp-adapters`；服务模式按需增加 PostgreSQL checkpointer 等驱动。应用使用的第三方 API 在冻结版本上完成探测后再写可执行样例。

生成并提交锁文件，记录验证过的版本组合；不要把“安装成功”当作兼容性通过。升级需重跑图恢复、消息序列化、Embedding 和 MCP 契约测试，保留旧版本工作进程处理未完成任务。

## 3. 配置层级

优先级：内置默认值 < 无密钥配置文件 < 环境变量；运行请求只允许覆盖受控字段。服务启动时验证配置并输出脱敏摘要，密钥使用环境变量或本机秘密管理机制。

| 配置 | 初始值或策略 |
| --- | --- |
| `APP_ENV` | `development` |
| `API_HOST` | `127.0.0.1` |
| `API_PORT` | `8000` |
| `DATA_DIR` / `ARTIFACT_DIR` | 项目数据目录 / 产物目录，启动时解析成绝对路径 |
| `BUSINESS_DB_URL` | 本地 SQLite 业务数据库 |
| `CHECKPOINT_DB_URL` | 独立 SQLite 检查点数据库 |
| `VECTOR_MODE` | `local`，仅工作进程访问 |
| `WORKER_CONCURRENCY` | `1` |
| `MODEL_MAX_CONCURRENCY` | `1`，探测后调整 |
| `MAX_SUBAGENT_CONCURRENCY` | `2`，仍受模型并发限制 |
| `TRACE_EXPORT_ENABLED` | `false` |
| `SANDBOX_ENABLED` | `false` |
| `RUN_EVENT_RETENTION_DAYS` | `30`，演示默认值 |
| `APPROVAL_TTL_HOURS` | `24` |
| `ALLOW_CLOUD_FALLBACK` | `false` |

Chat 与 Embedding 参数详见第 04 篇。预算变量与第 03 篇保持一致，集中建模，不让前后端各维护一套默认值。

## 4. 拟实现的操作入口

M0～M1 实现统一命令接口，名称可由实际代码落地调整，但功能必须齐全：

| 入口职责 | 应完成的工作 |
| --- | --- |
| `doctor` | 检查配置、存储目录权限、模型探测、维度与索引一致性 |
| `db migrate` | 执行业务迁移和 checkpointer 初始化，记录版本 |
| `api serve` | 启动接口与 SSE |
| `worker serve` | 领取任务、维持租约、处理恢复和导入 |
| `demo seed` | 幂等创建合成资料与演示项目 |
| `eval run` | 按数据集和配置执行评测并导出报告 |
| `index rebuild` | 暂存重建、验证和切换，不自动删除旧索引 |
| `data export` / `data restore` | 一致性备份和恢复校验 |

这里列的是入口契约，尚不能直接复制为运行命令。实施后应补充实际命令与输出样例。

## 5. 启动与停止顺序

首次：安装锁定依赖 → 配置模型 → 启动 LM Studio → Embedding 与 Chat 能力检查 → 初始化数据库 → 启动工作进程 → 启动 API 和前端 → 导入演示资料 → 执行烟雾测试。

正常启动先验证持久数据版本，再恢复租约过期任务；不要清空数据库“修复”运行状态。健康检查不能为每次探针重新加载模型。

正常停止：停止接收新运行 → 工作进程进入排空状态 → 等待当前安全边界保存 → 关闭 API 与存储。强制中断后由恢复流程接管；对已在外部执行的动作单独对账。

## 6. Windows 与容器网络

后端原生运行时，LM Studio 通常通过本机 loopback 地址访问。后端在 Docker Desktop 中时，容器内 `localhost` 指向容器自身，需使用可达宿主地址（通常为 `host.docker.internal`），并验证 LM Studio 监听范围与防火墙。

只开放所需访问范围；不要为了连通容器把所有服务无认证暴露到局域网。地址和端口以实际连接测试为准。前端不直接访问模型端点，避免暴露密钥和形成两套调用路径。

## 7. 资源控制

交互任务优先于批量索引，但通过队列配额防止导入永久饥饿。默认 Embedding 批量 8；超时或显存不足时递减批量并记录实际配置。Embedding 与 Chat 同机时以共享显存和并发测量结果调度。

大型文件先检查页数和文本规模，再解析；工具响应有字节上限；检查点和事件定期清理，但未完成运行与未解决审批不按普通保留期删除。

## 8. 数据与密钥

运行数据、模型文件、生成产物、真实 `.env` 和日志不提交 Git；只提交模板、合成样本、无秘密配置和锁文件。日志脱敏包括认证头、Cookie、URL 中的敏感参数和用户配置字段。

备份需要同时包含业务数据库、检查点、索引清单、向量数据、原文和产物。单机方案优先暂停写入后做一致性备份；SQLite 活跃 WAL 期间不能只复制主数据库文件。恢复后校验哈希和未完成操作记录。

云端追踪是可选能力，启用前明确其将接收哪些字段；默认只保留本地追踪。所有“离线模式”提示都应同时核对 Chat、Embedding、MCP 和追踪出口。

## 9. 排障速查

| 现象 | 优先检查 |
| --- | --- |
| Embedding 404 | base URL 是否含 `/v1`、路由是否重复拼接 |
| Embedding 401 | LM Studio 是否启用认证，token 是否匹配 |
| 模型不存在或未加载 | 使用真实模型 ID，检查模型类型和服务日志 |
| 中文召回差 | 模型中文能力、前缀、分词、切分与测试集 |
| 维度冲突 | 模型指纹是否变化，是否需新索引 |
| Agent 不调用工具 | Chat 模型及适配是否通过工具能力测试 |
| 重启丢任务 | 是否误用内存检查点、thread ID 是否变化 |
| 审批重复执行 | 稳定动作 ID、工具账本、外部幂等和恢复对账 |
| 页面消息重复 | SSE seq 去重、message delta 块序号和补播规则 |
| 数据库繁忙 | 是否误启多工作进程、事务是否包含慢模型调用 |
| 模型响应慢 | 冷启动、上下文长度、显存竞争、批量和并发 |

## 10. 可运维完成标准

新环境按文档完成首次启动；关闭重启后资料与任务状态不丢；能导出一次评测；能恢复一次备份；能定位某个 run 的模型、工具、索引和错误。实际步骤与文档一致后才能标记此项完成。
