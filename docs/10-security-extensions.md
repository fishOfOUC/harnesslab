# 10 安全与扩展协议

## 1. 信任边界

服务端身份、项目作用域和策略是权限依据。模型、检索文档、上传文件、技能正文、MCP 返回和历史记忆都不能授予权限。

本机开发模式仅绑定 loopback，使用服务端固定开发身份，并限制 CORS/Origin；进入局域网或公网前必须实现身份验证和资源授权，不能把“单用户模式”当作匿名公开服务。

本项目目标是让不可信文本无法绕过可执行控制。提示词防护仅作辅助，不承诺模型永不受注入影响。

## 2. 策略执行顺序

`校验工具存在及版本 → 校验输入 → 注入身份/项目作用域 → 校验资源 → 风险分类 → 校验预算 → 审批 → 执行前重检 → 执行及审计`。

工具真实 effect 与权限来自服务端注册表，不采信模型或第三方工具自行声明的“安全”。未知工具默认拒绝。审批允许执行当前具体操作，不能绕过原有资源权限。

| 操作类别 | 默认处置 |
| --- | --- |
| 本项目知识读取、受限计算 | 自动允许，记录日志 |
| 当前 run 下新建产物 | 允许，禁止覆盖和越界 |
| 修改既有产物、创建模拟工单 | 人工审批，参数版本绑定 |
| 删除资料或持久记忆 | 用户直接管理操作或特定审批流程 |
| 任意 Shell、宿主文件访问、未知网络出口 | 默认禁用 |
| 真实外部写操作 | 扩展时单独配置权限、审批、幂等和凭证 |

## 3. 文件工作区

按项目和 run 分配独立根目录。工具优先接受产物 ID；需要相对路径时执行规范化、根目录归属校验和存在性检查，禁止绝对路径、盘符、UNC、`..`、Windows 备用数据流及受限设备名。

拒绝通过符号链接或 junction 跳出根目录；避免先校验路径后由外部进程替换目标的竞态。文件写入通过专门工作区服务完成，使用不可预测临时文件、校验和原子提交。

限制文件数量、单文件大小、总工作区配额和允许类型。下载设置正确内容类型，HTML 等主动内容以附件处理；Markdown 渲染禁用原始危险 HTML，校验链接协议。

## 4. Skills 协议

项目技能与本次编写文档所使用的 Codex 技能是不同对象。以下是拟实现的 HarnessLab 技能目录格式：

```text
skills/technical-report/
  SKILL.md
  templates/report.md
  examples/example-input.md
```

```yaml
---
name: technical-report
version: 1.0.0
description: 基于授权资料生成带引用的技术比较报告
required_tools:
  - search_knowledge
  - read_source
  - write_report
input_schema: technical_report_request_v1
output_schema: technical_report_result_v1
---
```

加载器只接受管理员配置的本地技能清单，校验名称、版本、Schema 和引用路径，按需加载内容，并将内容哈希写入 run 快照。正文提供任务方法，权限仍由工具注册表决定。

技能文件不能通过 `required_tools` 自动安装服务、执行脚本或扩大网络出口。技能代码执行属于独立受审查扩展；P1 仅支持提示、模板和受控工具组合。

## 5. MCP 接入

通过 `langchain-mcp-adapters` 集成 MCP 工具，统一包装成项目工具契约；框架接入方式参考 [LangChain MCP](https://docs.langchain.com/oss/python/langchain/mcp)。

P1 先接一个自建只读参考资料服务，可选 stdio 或受控 HTTP。配置清单包含 server ID、传输方式、工具白名单、Schema 快照、版本、超时和风险分类；这些是应用配置，不能误当适配库原生参数直接传入。

stdio 进程只能来自管理员预配置的命令和路径，模型不能构造启动命令。远程地址通过服务端白名单配置，不接受模型返回的新 URL 自动连接；HTTP 出口防止访问元数据端点和未授权内网目标。

工具发现是可用性信息，不是权限批准。服务端描述、资源和提示都视作不可信内容；工具 Schema 或版本变化时暂停受影响工具，重新验证后启用。使用命名空间防止与本地工具重名。

每次调用携带独立超时和取消信息，限制输出大小，记录 server/tool 版本、耗时与结果摘要。凭证只给对应服务，不把所有环境变量继承给子进程。连接中断时只重试满足安全条件的操作。

## 6. 代码执行沙箱（P2）

只有隔离环境自检通过后才启用。至少具备非特权用户、独立临时工作区、CPU/内存/进程数/磁盘/时间限制、默认禁网、受控只读输入和可审计输出；禁止挂载宿主根目录、用户主目录和 Docker socket。

超时需要销毁整个执行单元，清理子进程；产物导出经过大小、路径和文件类型校验。容器提供隔离基础但不是所有威胁模型下的完整安全保证；更强隔离可评估专门沙箱或虚拟机方案。

在宿主直接运行 Python subprocess 只属于进程执行，不能标注为沙箱。缺少隔离环境时返回 `SANDBOX_UNAVAILABLE`，不能静默降级到宿主执行。

## 7. 数据生命周期与审计

审计记录谁在何时对哪个项目、哪个 run、哪个参数版本作出何种审批或工具操作，保存结果摘要和外部回执。密钥与完整认证数据永不写入审计。

文档、记忆、日志、产物、检查点和备份分别设置保留策略。用户删除内容后立即阻断读取，后台清理派生副本；备份按明确保留期淘汰，不能声称线上删除立即移除所有离线备份。

本地日志不是不可篡改审计系统。若未来需要防篡改能力，可增加外部追加写存储或签名链，并单独验证。

## 8. 扩展完成清单

新增任一工具或技能必须补齐：输入输出 Schema、版本、权限、超时、输出配额、幂等与重试策略、审计字段、至少一个成功和一个失败用例。涉及副作用还需重复执行与结果不明测试；涉及网络或文件需越界测试。
