# 07 评测与测试方案

## 1. 评测原则

测试 Harness 的控制行为，也测试模型的任务质量。控制行为尽量使用确定性替身复现；模型质量使用真实模型重复运行。不能用一次演示成功证明系统可靠，也不能把替身结果当真实模型成绩。

保存机器配置、模型标识与 revision、依赖锁摘要、Prompt/技能/策略版本、索引版本、数据集版本、运行参数和时间。随机种子仅在服务支持时记录，不承诺完全确定性。

## 2. 数据集

M1 最小集 30 条：普通知识问答 10、多文档问题 5、无答案问题 5、计算及工具问题 5、异常问题 5。

M5 完整集扩展至 100 条：单文档 20、多文档 15、无答案 10、工具选择与参数 15、审批与恢复 15、注入与隔离 15、长上下文与记忆 10。各类标签互斥用于计数，也允许额外能力标签。

样本 Schema：`case_id`、`category`、`question`、`fixture_version`、`expected_source_spans`、`required_facts`、`forbidden_facts`、`expected_tools`、`expected_policy_events`、`acceptance_rule`。答案允许合理改写，不做整段字符串完全匹配。

开发调参集与最终展示测试集分开；检索参数不能在测试集上反复挑最优而不披露。资料、预期答案及合成方法进入版本控制。

## 3. 质量指标

| 指标 | 计算方式 | 初始目标 |
| --- | --- | --- |
| Recall@8 | 每题命中的 gold 证据单元数 / gold 总数，再宏平均 | ≥ 0.85 |
| MRR@8 | 第一条相关证据的倒数排名，未命中为 0 | 报告实测值 |
| 引用有效率 | 可解析、授权、版本正确的引用 / 全部引用 | 1.00 |
| 引用支持率 | 人工判定被来源支持的被引用事实 / 被引用事实数 | ≥ 0.90 |
| 事实正确率 | 满足 required_facts 且不出现 forbidden_facts 的比例 | ≥ 0.85 |
| 无答案处理率 | 无证据题正确说明证据不足的数量 / 无证据题数 | ≥ 0.90 |
| 任务成功率 | 满足该样本全部验收规则的 run / 全部 run | ≥ 0.80 |
| 工具参数有效率 | 首次 Schema 校验通过的请求 / 工具请求总数 | ≥ 0.95 |
| 越权阻断率 | 被后端阻断的违规请求 / 构造违规请求 | 1.00 |
| 恢复成功率 | 满足恢复断言的故障用例 / 故障用例 | 1.00（固定回归集） |

gold 证据以文档版本和原文范围定义，再映射到不同 chunk 配置，避免重切分后指标失真。无答案题不参与 Recall/MRR 的分母，单独评价。

这些是项目验收阈值，不是已取得的成绩。小数据集同时展示分子/分母；关键质量用例运行至少 3 次并报告波动。

## 4. 性能与资源

记录排队时长、首次状态事件、首 Token、端到端时长、检索耗时、Embedding 吞吐、模型/工具调用次数、输入输出 token、峰值内存和可获取的显存用量。

区分冷启动和热启动；固定上下文和并发；每种性能配置至少 30 次。预算与外部费用用 provider usage 或显式估算记录；未知数据不补零。本地模型可报告耗时与资源，不把电费或总成本推算成已测事实。

## 5. 测试层级

- 单元测试：预算预留、权限裁决、路径归一化、引用校验、工具参数校验、索引指纹、幂等键规则。
- 契约测试：LM Studio 响应适配、MCP 结果包装、API 错误格式、SSE 补播和审批 revision 冲突。
- 集成测试：导入到检索、数据库持久化、租约竞争、取消与审批竞态。
- 端到端测试：上传 → 提问 → 点引用 → 写报告 → 审批 → 重启恢复 → 下载。
- 真实模型评测：固定数据集，采集质量与性能，不强求精确措辞。

## 6. 必测故障边界

| 场景 | 注入点 | 断言 |
| --- | --- | --- |
| 创建任务后崩溃 | 数据库已提交、工作进程未领取 | 重启可领取一次 |
| 生成时断开 | 模型流中途断连 | 记录不完整消息；重试不拼接成伪造答案 |
| 审批等待时崩溃 | checkpoint 与审批均持久化后 | 页面恢复同一待审批版本 |
| 中断记录部分落盘 | checkpoint 和审批业务记录之间 | 恢复协调器重建或核对，不能丢失门禁 |
| 写操作后崩溃 | 工单事务已提交，图节点未完成 | 工单数量仍为 1 |
| 写操作结果不明 | 外部模拟返回超时但可能已提交 | 不自动重复写，进入人工核对 |
| 两次批准 | 并发提交同一审批 revision | 只有一个有效决策 |
| 取消与批准竞争 | 两个请求同时提交 | 遵循事务顺序，无取消后新提交操作 |
| 预算并发竞争 | 两子任务同时预留最后余额 | 总预留不超过上限 |
| SSE 断开重连 | 接收部分 delta 后刷新 | 消息不重复，终态一致 |
| 索引批次失败 | 一半 chunk 写入后中断 | 未完成版本不可见，重试不重复 |

## 7. 安全评测

直接和间接提示注入、跨项目 ID、伪造引用、被删除资料引用、路径穿越、Windows 盘符/UNC/符号链接、恶意 MCP 工具描述、超大工具结果、重复调用、恶意记忆内容均进入回归。

P2 沙箱额外测试网络访问、宿主挂载读取、进程逃逸边界、超时子进程清理和资源耗尽。不通过时禁用该能力；普通 subprocess 不得标注为安全沙箱。

## 8. 对照实验

至少提供三组实验：向量 vs 混合检索；无压缩 vs 压缩；单 Agent vs 固定多 Agent。每次只改变一个主要变量，共用资料、测试样本和预算。

LLM 裁判可作为辅助，记录裁判版本并隐藏候选身份、随机交换候选顺序。引用支持、权限和副作用结果不只由 LLM 裁判决定。抽样人工核对，报告分歧。

## 9. 发布门槛

P0：30 条数据集可重复运行；核心闭环通过；权限、预算、引用存在性、幂等和重启恢复确定性测试全部通过。

完整展示版：100 条结果报告齐全；上述质量目标达成或在文档显式标注限制；控制类回归全部通过；十五分钟演示彩排至少两次；无真实密钥或用户资料进入仓库。

每份评测报告包含范围、环境、版本、样本规模、成功与失败数、分类指标、代表失败、改进建议和原始 run 链接。没有执行的测试标记“未执行”。
