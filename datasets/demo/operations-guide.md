# 运维与恢复操作指南

> 演示数据。仅用于展示故障恢复与审批流程，不构成真实运维规范。

## 1. 故障恢复要求

1. 工作进程崩溃后，系统必须在 30 秒内开始续跑，不包含人工等待时间。
2. 恢复顺序：取得新租约与 fencing token → 核对图版本与检查点 → 查询未完成操作 → 对账已知结果 → 持久化恢复事件 → 继续执行。
3. 恢复不保证外部副作用 exactly-once；重复副作用由工具操作账本与外部幂等机制避免。
4. 外部操作状态不明确时，必须停止自动执行并进入人工核对，不得把“再次批准”等同于安全重试。

## 2. 人工审批规则

- 需要审批的操作：修改既有产物、创建工单、任何真实外部写操作。
- 审批载荷必须包含：工具名、规范化参数、参数哈希、目标资源、预期影响、有效期。
- 一次批准只绑定该参数版本；用户修改参数后需重新确认，旧批准立即失效。
- 审批等待时间不计入活跃执行时长，但有独立的过期时间（默认 24 小时）。

## 3. 取消语义

取消信号在模型调用前后、工具执行前后与重规划边界检查。
已经提交的副作用必须写入取消结果，如实记录，不能声称已撤回。

## 4. 预算与限制

活跃运行 180 秒、模型调用最多 20 次、工具调用最多 30 次。
达到任一硬限制后停止新动作，并保留已有产物与中间结果。
