# 接入网关技术规范 v2

> 演示数据。本文中的容量与性能参数为虚构案例值，不代表任何真实系统结论。

## 1. 定位

v2 用**持久化队列**替代同步转发。网关先把请求写入队列并返回受理标识，由工作进程异步消费。

## 2. 与 v1 的差异

| 项目 | v1 | v2 |
| --- | --- | --- |
| 调用方式 | 同步转发 | 队列异步消费 |
| 单实例并发上限 | 20 | **50** |
| 过载策略 | 直接拒绝 429 | 入队缓冲，超过队列上限才拒绝 |
| 失败处理 | 不重试 | 只对可重试错误按上限重试 |
| 审计 | 无 | 记录操作意图、幂等键与结果 |
| 写操作 | 立即执行 | 需要审批的写操作先挂起 |

## 3. 并发与容量

- 单实例并发上限：**50**。
- 队列最大长度：5000 条；超过后拒绝新请求并返回 429。
- 消费侧并发：默认 1，可按机器资源提高；同一任务不会被两个消费者同时处理。

## 4. 幂等与重试

1. 每个副作用操作先持久化操作意图与幂等键，再执行，再保存结果。
2. 结果不确定时进入人工核对，不自动重试。
3. 只对明确可重试的读操作或具备幂等保证的写操作做退避重试。

## 5. 与 v1 的冲突说明

v1 第 3 节“后端失败时立即返回错误、不重试”与 v2 第 4 节的受控重试规则冲突。
v2 明确替代 v1 的过载策略与失败处理部分；v1 的超时数值在 v2 中未重新定义，仍按 v1 执行。
